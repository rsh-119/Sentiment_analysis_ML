# IMDB Sentiment Analysis

Binary sentiment classification on the IMDB 50k movie review dataset, implemented
as three independent approaches — a baseline LSTM, a Word2Vec-initialized
bidirectional LSTM with explicit negation handling, and a fine-tuned DistilBERT
transformer — trained and evaluated under an identical, leakage-free protocol so
their results are directly comparable.

## Results

| Model | Architecture | Test Accuracy | Notebook |
|---|---|:---:|---|
| LSTM | Trainable embeddings → LSTM(100) | 0.88 | [`notebooks/sentiment_analysis_part1.ipynb`](notebooks/sentiment_analysis_part1.ipynb) |
| BiLSTM + Word2Vec | Word2Vec embeddings + negation tagging → BiLSTM(100) | **0.90** | [`notebooks/sentiment_analysis_2.ipynb`](notebooks/sentiment_analysis_2.ipynb) |
| DistilBERT | Fine-tuned `distilbert-base-uncased` | 0.88 | [`notebooks/Sentiment_analysis_transformer.ipynb`](notebooks/Sentiment_analysis_transformer.ipynb) |

Full precision / recall / F1 breakdowns are in each notebook's evaluation section.

The BiLSTM + Word2Vec model edges out the other two on this run, plausibly
because explicitly tagging tokens that follow a negation (`NOT_worth`,
`NOT_recommend`, ...) combined with a bidirectional encoder captures signal the
plain LSTM's simpler preprocessing misses. Treat this as a single-run
comparison rather than a rigorous ablation — none of the three models were
tuned to their full potential (DistilBERT, for instance, was fine-tuned for
only 3 epochs at `max_length=128`), so the ranking could shift with further
tuning on any of them.

## Methodology

Every notebook uses the same **70 / 15 / 15 train / validation / test split**:

- **Validation** drives early stopping and best-checkpoint selection during training.
- **Test** is touched exactly once, at the end, purely for the metrics reported above.

This separation matters: reusing the validation set as the reported "test" set
(a common mistake) inflates results, since the model or its stopping point was
implicitly selected to perform well on that data. Preprocessing artifacts fit
on training data only (vocabulary for text vectorization, Word2Vec embeddings)
are likewise fit exclusively on the training split, never on validation or test.

## Getting Started

### Prerequisites

- Python 3.10+
- (Optional) an NVIDIA GPU for faster training — see [GPU Configuration](#gpu-configuration)

### Installation

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m ipykernel install --user --name sentiment-imdb --display-name "Python (sentiment-imdb)"
```

### Running the notebooks

Open any notebook and select the **Python (sentiment-imdb)** kernel. Run
notebooks from the `notebooks/` directory (Jupyter's default working
directory) — each one loads the dataset via a path relative to its own
location (`../dataset/IMDB Dataset.csv`).

`requirements.txt` pins `torch` to a `cu129` build via `--extra-index-url`.
On a machine without an NVIDIA GPU this still installs and runs correctly on
CPU — it's simply a larger download than a CPU-only wheel would be.

## GPU Configuration

Getting both PyTorch and TensorFlow onto the GPU cleanly required two fixes
beyond a plain `pip install`. Both are wired into the `sentiment-imdb`
kernelspec (`~/.local/share/jupyter/kernels/sentiment-imdb/kernel.json`) so
they apply automatically with no manual `export` needed:

| Issue | Cause | Fix |
|---|---|---|
| `torch.cuda.is_available()` returns `False` | The default PyPI `torch` wheel targets a newer CUDA (`cu130`) than the installed driver supports (`12.9`) | Install from `https://download.pytorch.org/whl/cu129` instead (already reflected in `requirements.txt`) |
| TensorFlow silently falls back to slow driver-side JIT compilation | XLA needs `libdevice.10.bc` (not bundled by `pip install tensorflow`) and a `ptxas` new enough for the GPU's compute capability — the system's `/usr/bin/ptxas` (CUDA 11.5) is too old | Set `XLA_FLAGS=--xla_gpu_cuda_data_dir=...` pointing at a `libdevice.10.bc` symlinked from the system CUDA toolkit, and prepend the newer `ptxas` bundled with the `triton` package (a `torch` dependency) onto `PATH` |

If the kernelspec is ever recreated from scratch, both `env` entries need to
be re-added, or GPU operations will either error out (PyTorch) or silently
run slower via driver-fallback JIT compilation (TensorFlow).
